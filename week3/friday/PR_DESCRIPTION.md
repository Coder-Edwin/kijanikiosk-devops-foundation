## Week 3 Friday: KijaniKiosk production server foundation

Tendo, this branch adds `kijanikiosk-provision.sh`, a single 8-phase script that converges a dirty VM to the production spec (my VM had been rebuilt, so as the brief allows I recreated the week's hand-made state with `tools/simulate-dirty-state.sh`: misconfigured accounts, a 777 config folder, a missing ACL entry, a hand-fixed logrotate file, uncommented ufw rules, a stray hold and Wednesday's weaker unit with a drop-in) and then proves it with per-check PASS/FAIL verification that exits non-zero on any failure; both run logs exit 0 with 78/78 checks passing, and the second run makes no changes at all. The main choices: all three units written inline with one shared hardening block (kk-payments 1.2, kk-api and kk-logs 1.1, with PrivateNetwork, PrivateUsers and DynamicUser deliberately rejected); a single config location under /opt with the /etc copy removed; logrotate `create 0660` plus `su kk-logs`, because 0640 silently caps kk-api at read-only through the ACL mask; `try-restart` in postrotate because no unit implements reload; ufw rebuilt from intent with the two port-3001 allows ordered before the deny; and stopping with exit 3 on a pinned-version mismatch instead of silently downgrading. With more time I would replace the SSH lockout guard with a bastion inside the monitoring subnet and verify the firewall from the generated rules file rather than by parsing `ufw status`. Reflection answers are in `week3/friday/reflection.md`.
