# Fault-Injection Log: kijanikiosk-ci

Every fault below is a real commit on `feature/week5-ci-pipeline`. Each fault commit is followed directly by a `git revert` commit that removes it. `tools/fault-drill.sh` built every commit, in order, through the real `kijanikiosk-ci` Jenkins job on the VM. Nothing was simulated. The commits are listed in `faults/drill-plan.txt` and `faults/drill-plan-3b.txt`. The full console log and stage table for every build are in `evidence/build-<n>-console.txt` and `evidence/build-<n>-stages.txt`. The drill summaries are `evidence/fault-drill-summary.txt` and `evidence/drill-plan-3b-summary.txt`.

**Reading the evidence:**
- **Skipped stages.** Jenkins' stage API reports a stage that was skipped after an earlier failure as `FAILED`, with a duration of 0.1–0.3 s. The console log is the authoritative record: it says `Stage "X" skipped due to earlier failure(s)`. The table below uses the console wording.
- **Test and Security Audit** run in parallel inside `Verify`, with `failFast true`.

## What the drill showed about the design

- **The line stops at the first failure.** In every fault, every stage after the failure was skipped, and no failed run published anything. Six of the seven fault builds failed before Publish was reached. The seventh (#17) reached Publish, and Nexus refused the duplicate.
- **Parallel Verify behaves as intended.** When Test failed (#11, #19), Security Audit still reported its result. Archive and Publish waited for both branches.
- **Every fault was followed by a green build** of the restore commit. Each green build published a new, distinct `<semver>-<git-sha>` version.
- **The drill found one real defect in the pipeline itself.** The failure notice named the wrong stage under parallel execution (#11). It was fixed in `4e02d89` and proven fixed in #19. Before the fix, the notice relied on one shared `LAST_STAGE` variable that every stage overwrote. After the fix, each stage sets `FAILED_STAGE` only in its own `post { failure }` block.
